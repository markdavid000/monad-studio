# MonGuard scans the workspace contract

"Scan for bugs" in the workspace now opens MonGuard, which sends the contract to an AI model on the server and lists likely vulnerabilities by severity. Each finding highlights its lines in the source, explains the impact and suggests a fix with code you can copy. The score is computed from the findings, and the page labels the result as AI analysis, not an audit.

## Changes

- Server AI core in `lib/server/`: validated server env (`GROQ_API_KEY`, `GROQ_MODEL` defaulting to `openai/gpt-oss-120b`, Upstash URL and token), one Groq client using Structured Outputs with the reply validated again by `zod`, a per IP limit of 20 AI calls per 10 minutes through Upstash, and `aiRoute`, which returns `{ data }`, or `{ error: { code, message } }` with 400, 429 (with `Retry-After`), 502 or 500.
- `lib/api-error.ts`: the client side of that contract (`postJson`, `ApiError`).
- `lib/severity.ts`: severity order and the score (critical 25, high 15, medium 8, low 3, info 1, from 100, floor 0).
- `features/monguard`: reply schema and mapper (sorted by severity, ids, line numbers clamped to the source, Markdown fences stripped from fix code), prompt with numbered source lines, `POST /api/monguard/scan`, `/studio/monguard` with idle, loading, success, no findings, out of date, too large, rate limited and error states.
- The contract draft hook moved to `src/hooks/` and the byte size helper to `src/lib/` now that two features use them.
- Workspace: "Scan for bugs" links to MonGuard; the sidebar and landing page link to it too.
- Vitest runs server tests in Node and component tests in jsdom.

## Removed

- `features/studio/hooks/use-contract-draft.ts` and `features/studio/lib/byte-size.ts` (moved, not duplicated).

## Verification

- Tests: score maths, reply mapping (valid, partial, unknown severity, empty, fences, line clamping), input limits, the route (success, non JSON, oversized, 429 with `Retry-After`, schema mismatch, non JSON reply, Groq down) with Groq mocked at `fetch`, and the page in every state.
- Live: the three workspace examples scanned against Groq with `openai/gpt-oss-120b`, about 4 seconds each, with the expected findings and line numbers.
- Headless Chrome at 1440px and 600px: idle, loading and result states, with the route answered from a live report because Upstash was not configured yet. The rate limit has not run against a real Upstash database.
